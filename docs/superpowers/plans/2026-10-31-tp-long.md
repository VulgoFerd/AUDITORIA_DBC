# TP 64-bit — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fazer o TP do JRMCore ser saldo de 64 bits, persistido, sincronizado e exibido sem o teto de 2.147.483.647.

**Architecture:** Patch de bytecode com ASM em três jars (JRMCore, DBC, npcdbc). O campo `JRMCoreH.curTP` muda de `int` para `long`, o que muda o descritor do campo no constant pool (`I` → `J`) e obriga reescrever toda referência ao campo. A nova chave NBT `jrmcTplong` vira fonte de verdade; `jrmcTpint` fica como espelho write-only. Tudo é validado estaticamente (`FrameCheck` + `VerifyJar`), porque não há teste em jogo disponível para o agente.

**Tech Stack:** Java 8 target (`javac --release 8`), ASM 9 (asm, asm-tree, asm-util), CFR 0.152 para leitura, jars oficiais em `nntdarkmp_copy\mods`.

**Spec:** `docs/superpowers/specs/2026-10-31-tp-long-design.md`

## Global Constraints

- Instância original `C:\Users\Fernando\nntdarkmp` **nunca** é tocada. Trabalho só em `nntdarkmp_copy` e em `artifacts/`.
- Todo jar gerado passa por `FrameCheck` antes de instalar. Um método com frame inválido reprova o jar inteiro.
- Target de bytecode: Java 8. Compilar com `javac --release 8`.
- Nenhum código do mod lê `jrmcTpint` de volta. Espelho é write-only.
- Os três jars viajam juntos. Não existe instalação parcial.
- Sem git: cada entrega vira `artifacts/<jar>-<tag>.jar` com SHA-256 registrado em `artifacts/SHA256SUMS.txt`.
- Nomes obfuscados do Minecraft (`func_74768_a` = `setInteger`, `func_74762_e` = `getInteger`, `func_74781_a` = `getTag`) não são renomeados.

## Review Focus

Os cinco modos de falha que mais provavelmente mordem o jogador, cobertos nas tarefas indicadas:

1. Jogador com saldo acima de 2,1 bi desconecta e reconecta — o saldo precisa voltar igual (Tarefa 4 e 10).
2. Mundo antigo, com NBT só de `jrmcTpint` — o TP existente precisa ser preservado, não zerado (Tarefa 2 e 10).
3. Saldo alto + npcdbc salvando o jogador — o TP não pode regredir para o valor do espelho (Tarefa 8).
4. Ganho de TP no teto antigo — nada pode ser descartado nem virar negativo (Tarefa 4).
5. `/jrmctp` com valor negativo e com valor acima de `Long.MAX_VALUE` — não pode estourar para positivo (Tarefa 6).

### Task 2: `JRMCoreH` — storage de 64 bits

**Files:**
- Create: `tools/TpPatch.java` (patcher por classe, entrada `--class <nome> --out <dir>`)
- Modify: `artifacts/JRMCore-v1.3.51-original.jar` → `artifacts/JRMCore-v1.3.51-tp-long.jar`
- Test: `VerifyJar` (Task 1)

**Interfaces:**
- Produces em `JinRyuu/JRMCore/JRMCoreH`:
  - `public static long curTP`
  - `public static long getTPLong(EntityPlayer)`
  - `public static void setTPLong(long, EntityPlayer)`
  - `public static String tpShort(long)`
- Consumes: `numSep(long)` e `numSepShort(long)` existentes.

- [ ] **Step 1: `VerifyJar --expect-long-curTP` no jar de saída deve falhar agora**

Run: `java ... VerifyJar artifacts/JRMCore-v1.3.51-tp-long.jar --expect-long-curTP`
Expected: FAIL — `curTP:I` encontrado em 8 classes.

- [ ] **Step 2: Trocar o tipo do campo `curTP`**

`TpPatch` reescreve a declaração do campo `curTP` de `I` para `J` em `JRMCoreH`.

- [ ] **Step 3: Adicionar `getTPLong` / `setTPLong` com migração**

Regra exata:
- `getTPLong(p)`: se `pres` tem `jrmcTplong`, retorna `getLong("jrmcTplong")`; senão `tp = getInt("jrmcTpint")`, grava `jrmcTplong = tp`, retorna `tp`.
- `setTPLong(v, p)`: grava `jrmcTplong = v` **primeiro**, depois `jrmcTpint = (int)min(v, Integer.MAX_VALUE)`.

- [ ] **Step 4: Adicionar `tpShort(long)`**

Corte em `10_000_000_000L`. Abaixo: `numSep(v)`. Acima: valor dividido pela potência e sufixo `B`/`T`/`Q`/`Qi`, com uma casa decimal truncada (`10.5B`). `v >= 10^21` não ocorre com `long`, mas o código usa `Qi` como último degrau.

- [ ] **Step 5: Substituir leituras e escritas internas de TP em `JRMCoreH`**

Todo `getInt(p, "jrmcTpint")` → `getTPLong(p)`. Todo `setInt(x, p, "jrmcTpint")` → `setTPLong(x, p)`. Todo `curTP` em aritmética passa a `long`; casts `(long)curTP` ficam no-op. Os clamps contra `getMaxTP()` em caminhos de saldo são removidos; os que protegem **custo** continuam.

- [ ] **Step 6: Verificar**

Run: `java ... FrameCheck artifacts/JRMCore-v1.3.51-tp-long.jar`
Expected: `0 invalid-frame methods`.
Run: `java ... ClassDiff artifacts/JRMCore-v1.3.51-original.jar artifacts/JRMCore-v1.3.51-tp-long.jar`
Expected: só `JRMCoreH` listado, com os métodos esperados.
